https://calpaterson.com/memoryfields.html

**Original Title**: Agent memory as a file format

### 主な設計思想と特徴
1. **プロンプトによる記述（Prose）**: 記憶を事実の断片ではなく、エージェント自身がMarkdown形式で記述した文章として保持します。これにより、複雑なチャンク分割や要約プロセスを不要にします。

## AIネイティブなSDLCはインフラストラクチャから始まる

https://metalbear.com/blog/ai-native-sdlc-infrastructure/

**Original Title**: The AI-Native SDLC Starts With Your Infrastructure

AIエージェントを活用した開発サイクルにおいて、モック環境ではなく本番に近い実環境での検証を可能にするインフラ整備が、エージェントの自律性とコード品質を左右することを提言している。

Anthropicが提唱するAIエージェント向けのSDLC（ソフトウェア開発ライフサイクル）プレイブックを軸に、AI時代における開発インフラの重要性を論じた記事です。執筆者は、コード生成が高速化された現在、ボトルネックは「検証（フィードバックループ）」へ移行したと指摘しています。

主な内容は以下の通りです：
- **検証の限界**: 従来の開発で用いられるフェイクやモック環境では、実環境との乖離によりAIエージェントが「テストは通るが本番では動かない」コードを出力するリスクがある。
- **mirrordによる解決**: ローカルのコードをKubernetesクラスターに接続するmirrordを活用することで、エージェントは実際のサービス、環境変数、データベースを直接利用してテストが可能になり、エージェントの判断精度が飛躍的に向上する。
- **スケーラブルな開発基盤**: mirrord Operatorを使用することで、トラフィックのフィルタリングやデータベースのブランチ化を行い、複数のAIエージェントが同一のステージング環境で干渉せずに並行稼働できる仕組みを構築できる。

AIにコードを書かせるだけでなく、それを正確に検証できる環境（Stage 4の自動化）の構築こそが、AIネイティブな開発組織への鍵となります。
