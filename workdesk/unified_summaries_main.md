## A2A実装におけるLoopjacking：人間による承認プロセスの乗っ取り

https://adithyanak.com/loopjacking-in-a2a-implementations/

**Original Title**: Loopjacking in A2A Implementations: Hijacking Human-in-the-Loop Approvals

A2Aプロトコルを用いたAIエージェントの承認フローにおいて、承認待ちの操作を密かに別の内容へ書き換える「Loopjacking」脆弱性の詳細と対策を詳述した研究レポート。

本レポートは、AIエージェント間の通信プロトコル（A2A）およびLangGraph Agent Serverにおける「Loopjacking」という新たな脆弱性を分析している。

- **脆弱性の核心**: 承認フロー（Human-in-the-Loop）において、承認者が操作内容を確認してから「承認」を送信するまでの短い間に、別の主体（メーカー）が同じタスクIDを用いて操作の引数や宛先を書き換えられる点にある。システムがタスクIDのみを承認の識別に利用し、具体的な操作内容（ペイロード）の整合性を検証しない場合に発生する。
- **実証実験**: LangGraph Agent Server 0.7.5から0.14.0の広範なバージョンにおいて、送金先と金額を承認直前にすり替える攻撃が成功することが確認された。承認者がAの内容を確認して承認ボタンを押しても、実際に実行されるのはすり替えられたBの内容となる。
- **根本的な対策**: 承認待ち状態のタスクに対する更新を禁止する認可ポリシーの適用、または操作内容全体のハッシュ値を承認記録に厳密に紐付ける「Action-Bound Approval（アクション拘束型承認）」の実装が不可欠である。A2A仕様の最新改訂（PR #2081）では、実装者が承認範囲を定義・検証すべき責任が明文化された。

## エージェンティック・コーディングの四騎士：スロップ、疎外、脱技能化、チームの崩壊

https://distantprovince.substack.com/p/the-four-horsemen-of-agentic-coding

**Original Title**: The Four Horsemen of Agentic Coding - by Alex Martsinovich

AIエージェントによる開発の普及が、コードの品質低下、開発者の所有権喪失、技能の衰退、そしてエンジニアチームの社会的断絶を招いていると警鐘を鳴らす論考。

AIエージェントを活用した開発（Agentic Coding）は非常に便利である一方、エンジニアリングの本質を損なう深刻な影響を及ぼしていると著者は主張し、それを「四騎士」になぞらえて解説しています。

1. **Slop（スロップ）**: AI特有の無機質で独特な臭いを持つコードが蓄積し、人間が保守したくない「AIの荒野」がコードベースに広がる。
2. **Alienation（疎外）**: 直接コードを書く体験が失われることで、職人としての道具への愛着や成果物に対する所有権が消失し、開発者が製品に無関心になる。
3. **Deskilling（脱技能化）**: 容易な解決策に依存することで既存のスキルが錆び付き、また「学習のインセンティブ」が失われることで、次世代の熟練エンジニアが育たなくなる。
4. **Team Fallout（チームの崩壊）**: メンバーが人間ではなくAIと対話するようになり、助け合いや専門性の尊重といったチームの社会的紐帯が弱まり、孤立したオペレーターの集まりへと変貌する。
