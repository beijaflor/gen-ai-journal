## エージェント・アクセス・モデル（AAM）：AIエージェント時代に向けたセキュリティの進化

https://blog.cloudflare.com/the-agent-access-model/

**Original Title**: The Agent Access Model

Cloudflareが提唱するAAMは、人間向けのZero TrustモデルをAIエージェントに最適化し、タスク単位のクレデンシャルと「トラストラチェット」による動的な権限制限を導入する。

Cloudflareは、人間を前提とした従来のZero Trust（BeyondCorp）モデルでは不十分な、AIエージェント専用の新しいセキュリティフレームワーク「Agent Access Model (AAM)」を提唱しました。AIエージェントは短寿命でありながら高速かつ多段階の権限委譲を行うため、従来の手法では過剰な権限付与や検知の遅れが課題となります。

### AAMの主要なコンポーネントと仕組み
1. **タスク単位のアイデンティティ**: タスク実行時のみ有効な、送信元制限（Sender-constrained）付きの短寿命トークンを発行します。
2. **トラストラチェット (Trust Ratchet)**: 本モデルの核心であり、エージェントが機密データに触れた際、そのタスクの残りの能力（外部へのデータ送信など）を一方向に自動制限します。これにより、機密情報へのアクセスと外部通信の同時成立を防ぎます。
3. **プロンプトではなく基盤で制御**: 制限はプロンプト（AIへの指示）ではなく、ハーネス（実行環境）とネットワーク層で強制されます。
4. **継続的な最小権限の改善**: 実際の行動ログ（Agent Activity Log）を分析し、将来のタスクテンプレートに対して権限の過不足を提案するループを回します。

現時点では、共有ワークスペースにおける「マルチプレイヤー・アクセス制御（複数ユーザーの権限混在）」が大きな技術的課題として残されていますが、AAMはエージェントを制御可能な「計測されたソフトウェア」として扱うための道筋を示しています。

## Leanカーネルの健全性バグ#14576に関するポストモーテム

https://leodemoura.github.io/blog/2026-8-1-postmortem-for-kernel-soundness-bug-14576/

**Original Title**: Postmortem for Kernel Soundness Bug #14576

Leanカーネルの入れ子になった誘導型の処理に存在した、偽の命題を証明可能にする健全性の脆弱性とその修正、およびAIを活用したさらなるバグ発見の取り組みについての報告。

### 概要
Lean 4のカーネルにおいて、入れ子になった誘導型（nested inductive types）のパラメータ処理に不備があり、健全性が損なわれるバグ（#14576）が発見・修正されました。このバグは、AIを用いて生成されたコラッツ予想の「偽の証明」をきっかけに特定されました。

### 技術的詳細
バグの本質は、カーネルが入れ子になった出現箇所を処理する際、パラメータがコンストラクタのフィールドに現れない「ファントムパラメータ」である場合に、生成された補助型からこれらが消失し、型チェックをすり抜けてしまう点にありました。これにより、不適切な引数を用いて `False` の証明をカーネルに受理させることが可能になっていました。これはメタ理論の欠陥ではなく、実装上の不備です。

### 検証と対策
- **独立したチェッカー**: Rust実装の `nanoda` も偶然別のバグを抱えていましたが、修正されました。複数の独立したカーネルによる検証の有効性が改めて示されました。
- **AIによる監査**: OpenAIのサイバーセキュリティ専門AIを活用し、他にも複数のプログラミングミスを特定・修正しました。これらはメタプログラミング経由でのみ到達可能なものでした。
- **今後の展望**: Lean FROはカーネルの不変条件を強化し、`lean4lean`（Lean自身によるLeanの形式化）などのプロジェクトを通じて、検証済みカーネルの構築に向けた支援を継続します。
