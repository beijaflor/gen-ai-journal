### Git worktreeはコーディングエージェントの隔離境界にはならない
**原題**: Git worktrees are not an isolation boundary for coding agents
**カテゴリー**: セキュリティ・リスク
**URL**: https://fletch.sh/blog/git-worktrees-vs-clones-for-ai-agents/

AIコーディングエージェントを並列稼働させる際、多くのツールがGit worktreeで作業環境を分離しているが、これは安全対策として機能しないという警告。worktreeは`.git/hooks`や`.git/config`、スタッシュを元リポジトリと共有するため、エージェントがホスト上で任意コードを実行したりコミット履歴を改変したりする余地が残る。検証によれば、ローカルの`git clone --shared`はディスクコストと生成速度でworktreeとほぼ互角でありながら、設定とフックを確実に隔離できるという。人間の並行作業にはworktreeで十分でも、自律的に動くエージェントには足場が違う——「隔離しているつもり」で運用しているチームへの静かな警鐘だ。

### LLMルーターは不要か？Manifestが自動ルーティング機能を廃止した理由
**原題**: Everyone is building LLM routers, we deprecated ours
**カテゴリー**: ビジネス・戦略
**URL**: https://manifest.build/blog/why-we-deprecated-our-llm-router/

コスト削減のためリクエスト内容に応じてモデルを自動振り分けする「LLMルーター」が業界のトレンドとなる中、LLMゲートウェイのManifestはこの主力機能を自ら廃止した。7,000人分のユーザーフィードバックから浮かび上がったのは、プロンプト単体ではタスクの複雑さを判断できないこと、プレフィックスキャッシュの方がコスト削減に効くこと、モデルの動的切り替えが出力の一貫性を損ない評価やプロンプト管理のコストを増やすことという逆風だった。結論は明快で、エンジニアが意図を持ってモデルを選び、その癖に習熟する方が長期的な品質と信頼性で勝るという、自動化礼賛への異論だ。

### 複数のSymphony（OpenAI AIエージェント）をSlackで一元管理する「Orchestrators」の開発
**URL**: https://hiroppy.me/blog/posts/introduce-orchestrators

**URL**: https://blog.shibayu36.org/entry/2026/07/27/163000

### AIエージェントにGCPの調査を任せるため、readonly専用のgcloud configurationを用意する
**URL**: https://blog.shibayu36.org/entry/2026/07/29/173000

Claude CodeなどのコーディングエージェントにGCP環境の調査を任せたいが、誤操作で本番リソースを書き換えられては困る——という現場感覚から出発した実践記。解決策はroles/viewerのみを付与した専用サービスアカウントを用意し、それを借用（Impersonation）する専用のgcloud configurationを構築すること。コマンド一つで「読み取り専用」状態と通常の作業状態を切り替えられる設計で、設定コマンドの具体例に加え、実際に書き込み操作が拒否されることまで検証済みだ。凝った権限管理ツールを新設せずとも、既存のgcloud機能の組み合わせだけで安全なエージェント運用環境を作れる点が、今日から試せる実務的な価値を持つ。

### AIの推論は「間違った理由」に基づいているのか？
**原題**: Is AI Reasoning Right for the Wrong Reasons?
**URL**: https://www.quantamagazine.org/is-ai-reasoning-right-for-the-wrong-reasons-20260731/

大規模推論モデル（LRM）が数学の難問を解く際に示す「思考の連鎖」は、本当に論理的推論の記録なのか。サンタフェ研究所のメラニー・ミッチェル氏やアリゾナ州立大学のスバラオ・カンバムパティ氏らは、最終回答と思考の連鎖の間に必ずしも因果関係がなく、無意味なトークンの羅列でも同等の結果が得られる場合があると指摘する。彼らはこれを「願望に基づいた記憶術」と呼び、モデルが人間のように考えていると錯覚することの危険性を警告する。目覚ましい正解率の裏で進んでいるのは、実は精緻な近似検索に過ぎないのかもしれない——「正しい答えを間違った理由で」導き出すブラックボックスと、科学はどう向き合うべきかを問う一本。

### Claude Opus 5に「---」を送ると地図製作者に関する5,000トークンの文章が生成される現象の調査
**原題**: I sent Claude Opus 5 "- – -" and it wrote me 5k tokens about a cartographer
**カテゴリー**: ニッチ・深堀り
**URL**: https://austinsnerdythings.com/2026/07/28/claude-opus-5-dangling-document-effect/

Claude Opus 5に「---」のような区切り記号だけを送ると、なぜか地図製作者をめぐる長大な創作文章が返ってくる——そんな奇妙な挙動を600回超のAPIコールで検証したレポート。原因はマークダウン構文（`---`や`##`）そのもので、モデルはこれを「補完すべき未完の文書ファイル」と誤認しているらしい。生成タイトルの約9%に「地図製作者」が登場し、とりわけ「不在」や「未完成」をテーマにした創作を好む偏りも判明した。自分の生成文をユーザー発言と誤認して自問自答を始めたり、特定文字列に謎の拒否反応を示す事例もあり、システムプロンプトで「あなたは対話型アシスタントだ」と明示するだけでこの現象は完全に抑制できるという。ベアメタルAPI利用時のプロンプト設計の重要性を突きつける調査だ。

### Physical AIにおけるGPT-5.6対Claude Fable 5：どちらが最高の結果を出すか？
**原題**: GPT-5.6 vs Claude Fable 5 for Physical AI, which performs best? - Blog | JuliaHub
**URL**: https://juliahub.com/blog/frontier-models-physical-ai-evaluation

JuliaHubがNASAのHL-20飛行体シミュレーションなど5段階の難問でOpenAIの「GPT-5.6」系とAnthropicの「Claude Fable 5」の物理モデリング能力を検証したベンチマーク。最高精度はClaude Fable 5（加重スコア0.889）だが1試行9.60ドルと高額で、GPT-5.6 Solはスコア0.814ながら約5分の1のコスト（1.74ドル）で実務向けバランスに優れる。逆にGPT-5.6 Lunaは精度・コスト・速度すべてで最下位という結果に終わった。最も注目すべきは、モデル間の性能差（0.162ポイント）よりも専用の「Dyad AIハーネス」の有無による差（0.366ポイント）の方が大きかった点で、物理AIの成否を左右するのはモデル単体の能力以上に、ソルバーとの検証ループを組む実行基盤の設計にあると示唆している。

### 最初のプロンプトを超えて：AIエージェントの多段階コード生成を評価する新ベンチマーク「EvoCode-Bench」
**原題**: Evaluating Agents Beyond the First Prompt
**URL**: https://www.philschmid.de/evocode-bench

SWE-benchのような単発タスク評価では見えない、AIエージェントの「継続的な開発力」を測る新ベンチマーク「EvoCode-Bench」。5〜15ラウンドにわたり要件追加や仕様変更が続く現実的な開発サイクルを再現したところ、第1ラウンドで46.7%あった合格率は第10ラウンドには7.7%まで急落した。失敗の主因は新機能が作れないことではなく、共通コードパスの誤編集で既存の動作を壊してしまう「回帰バグ」にある。一方、プロジェクトプランや仕様を永続ドキュメントとして管理し続けたエージェントは成功率が2倍以上に向上しており、トップティアモデルであっても過去の自分のコードを保守し続ける能力にはまだ大きな伸び代があると結論づけている。

### 説明可能AI(XAI)の現状と展望
**カテゴリー**: 教育・学習
**URL**: https://kaityo256.github.io/explainable-ai-review

機械学習のブラックボックス問題に挑む「説明可能AI（XAI）」を、定義・歴史・最新規制まで一望できる総論。XAIを「説明可能性」「信頼性」「確実性」の3軸で整理し、エキスパートシステムから2017年のDARPAプロジェクト、現在の深層学習へと至る系譜をたどる。ハルシネーションや敵対的サンプル、狼とハスキーを取り違える偽の相関といった課題に対し、Grad-CAMなどの可視化手法が紹介される一方、その説明自体も欺瞞可能だという脆弱性も指摘される。ユニークなのは、イジングモデルなど統計力学を用いてニューラルネットワークの内部を解析する物理学的アプローチを、「嘘のつけない客観的理解」として位置づける視点で、EU AI ActやNISTの規制動向まで含めた射程の広さが光る。
