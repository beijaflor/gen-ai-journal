**Original Title**: GitHub - getkern/kern: A fast, rootless sandbox and virtual resource runtime for any workload, including untrusted and AI-generated code. Daemonless: a real, kernel-enforced container in ~3.5 ms from an OCI image, out of one static binary

Rust製の単一バイナリで動作し、OCIイメージを3.5msで起動可能な、AI生成コードの実行に最適な高速・ルートレス・デーモンレスのサンドボックス環境。

kernは、信頼できないコードやAIが生成したコードを安全かつ高速に実行するために設計された、Rust製のサンドボックスおよび仮想リソースランタイムです。

### 主な特徴
- **超高速な起動**: OCIイメージからの起動が約3.4ms、ベア環境では約2.4msと、DockerやPodmanと比較して100倍近く高速です。AIエージェントのツール実行ごとに個別の環境を割り当てる運用が現実的になります。
- **デーモンレス & ルートレス**: 単一の静的バイナリのみで動作し、バックグラウンドプロセスを必要としません。常に非特権ユーザー（rootレス）で動作するため、ホストOSへの影響を最小限に抑えます。
- **AI・開発ツールとの統合**: Python、Node.js、MCP（Model Context Protocol）向けのライブラリを提供。LangChainやエディタ（Cursor等）からローカルなコードインタープリタとして容易に利用可能です。
- **カーネルによる強力な隔離**: Linuxの名前空間（Namespace）、cgroup v2、seccomp（デフォルト拒否）、Landlockなどの機能を活用。リソース制限やネットワーク遮断をカーネルレベルで強制します。

### 補足
libc以外の依存関係を持たない純粋なRust実装であり、Docker Composeファイルをそのまま読み込んでスタックを起動する互換機能も備えています。Linux、WSL2、ARM（Raspberry Pi等）をサポートしています。

## ChatGPTの広告ターゲティングは「ゴミ」レベル：実際の運用データによる検証

https://successfulsoftware.net/2026/09/02/chatgpt-ad-targeting-is-garbage/

**Original Title**: ChatGPT ad targeting is garbage | Successful Software

ChatGPTの有料広告を実際に運用した結果、Google広告に比べコンバージョン率が10分の1以下という、極めて質の低いターゲティング実態が明らかになった。

ソフトウェア開発者のAndy Brice氏が、自身の座席表作成ソフト「PerfectTablePlan」を用いてChatGPTの有料広告をテストした詳細なレポートです。

### 運用の主要データ
約3,000クリックを獲得し、クリック単価（CPC）は£0.10と非常に安価でしたが、コンバージョン率は0.46%という衝撃的な低さでした。同期間のGoogle広告のコンバージョン率（5.3%）や、ChatGPTからの無料リファラル（4.2%）と比較しても、その質の低さは明白です。

### 低パフォーマンスの要因分析
広告詐欺の専門家であるAugustine Fou博士の協力により、トラフィックを詳細に分析しました。その結果、クリックの約70%は人間によるものでしたが、滞在時間の平均はわずか7秒で、マウス操作はあってもクリックなどのアクションに繋がらない「意欲の低い訪問者」が送り込まれていることが判明しました。

### 結論と教訓
著者は、ChatGPT側が収益を最大化するために、広告の文脈を無視して質の低いトラフィックを無理に割り当てている可能性があると指摘しています。ChatGPTの「無料リファラル」は質が高い一方で「有料広告」が機能していない現状を受け、広告主はクリック数という虚栄の指標に騙されず、実際の成約を基準に判断すべきだと結論付けています。

## WebMCPがアツいので見てほしい

https://dev.classmethod.jp/articles/webmcp-introduction/

WebMCPは、Webサイトの機能を構造化されたツールとしてAIエージェントに公開し、人間とAIが同じUIを介してシームレスに協調できるようにする新しいWeb標準案です。

この記事では、W3Cで議論されているWebMCP（Model Context ProtocolをWebブラウザ上で実現する仕組み）の革新性について解説しています。WebMCPは、サイト側が「宣言型（HTML属性）」または「命令型（JavaScript）」のAPIを用いて、AIが利用可能な機能を構造化データとして定義します。これにより、従来のBrowser UseのようにAIが画面を推測して操作する際の不安定さを解消し、高い精度でフォーム入力や設定変更を自動化できます。最大の特徴は、人間向けのUIを維持したまま、AIも同じコンテキストで操作可能になる「エージェントアクセシビリティ」の視点です。記事内では経費申請やスライド編集のデモを通じ、ユーザーが自前のAIエージェントを使いつつサイトと対話する未来のWeb体験を提案しており、同時にプロンプトインジェクションやセキュリティ上の懸念点についても言及されています。

Simon Willison氏による、OpenAIの「ChatGPT Work」に関する詳細なレビュー記事です。ChatGPT Workは、従来のChatとは一線を画す「タスク完遂」のためのプロダクトとして位置付けられています。主な特徴として、まずインターネット接続が完全に許可されたコード実行環境が挙げられ、GitHubリポジトリのクローンやAPI連携が可能です。また、ヘッドレスChromeを操作しJavaScriptを実行できるブラウザツール、セッション間で共有される永続的なファイルシステム、Cloudflare Workersを用いたWebサイト構築機能（ChatGPT Sites）など、極めて強力なツール群が統合されています。モデル面ではGPT-5.6（Sol, Luna, Terra）の各推論レベルが選択可能。一方で著者は、機密データへのアクセスと外部通信が組み合わさることによるプロンプトインジェクション攻撃への脆弱性（Lethal Trifecta）についても懸念を示しており、機能の強力さと引き換えにセキュリティ面での理解が不可欠であると説いています。
