## Codex Cloudを利用してコード修正してもらっていたら本名が駄々洩れしていた話

https://blog.hitsujin.jp/entry/2026/10/05/codex-cloud-git-author

OpenAIのCodex Cloudを利用した際、GitのAuthor設定がOpenAIアカウントの本名になっており、意図せずパブリックリポジトリに個人情報が流出してしまった実体験に基づく注意喚起。

OpenAIの新機能「Codex Cloud」のGitHub連携を利用して開発を行った際、意図せず本名が公開されてしまったトラブルの備忘録です。

### トラブルの経緯
クラウド環境でAIにコード改修を指示し、プルリクエスト作成まで自動で行ったところ、GitHub上のAuthor（作成者）情報が自身の本名になっていました。OpenAIのアカウント登録情報がGitのAuthor設定に自動反映されていたことが原因です。

### 対応と教訓
Force PushでAuthor情報を書き換えても、GitHubのプルリクエスト履歴には古いSHAが残り、過去のコミット内容（本名を含む）が閲覧可能な状態でした。最終的にリポジトリ自体を削除して対応せざるを得なくなりました。

### 対策
クラウド型のAI開発環境を利用する際は、ChatGPTのプロフィール名ではなく、OpenAI側の「アカウント登録情報」が使用される可能性を考慮する必要があります。環境セットアップ後、指示を出す前に必ず`git config`等でAuthor設定を確認・変更することが推奨されます。

### 法律の「保守性」とリファクタリング
ソフトウェア開発において、内部構造を整理する「リファクタリング」は不可欠です。安野氏は、積年の改正が積み重なった現代の法律にも同様の「保守性の悪化」が生じていると指摘します。特に「対面」や「書面」を前提とした古い表現（アナログ規制）がデジタル化の大きな障壁となっています。

### 技術的特徴
- **階層化された「スタック」構造**: セッション開始時の短い指示、中心スキル（poteto-mode）、23種類のプレイブック（手順書）、23種類の原則（判断基準）が階層化されており、必要な時だけ詳細を読み込むことでコンテキストを効率化しています。

## 本番環境で信頼性の高いAIエージェントシステムを構築する方法

https://www.oreilly.com/radar/how-to-build-reliable-ai-agent-systems-for-production/

**Original Title**: How to Build Reliable AI Agent Systems for Production – O’Reilly

AIエージェントの信頼性はプロンプト調整だけでは不十分であり、決定権限の分離、文脈の検証、最小権限の原則、状態の保存といった堅牢なシステム設計が不可欠である。

AIエージェントを実験段階から本番環境へ移行させるためには、モデルの出力に依存しすぎない「システムとしての設計」が重要です。本記事では、信頼性を確保するための具体的なアプローチを提唱しています。

1. **決定層の分離**: モデルにはアクションを提案させ、決定・執行は決定論的なポリシーサービスで行う分離構造を導入します。
2. **信頼できない文脈の管理**: エージェントが参照するメモリやファイルは「信頼できない入力」として扱い、履歴（Provenance）の記録と検証を行います。
3. **最小権限の原則**: 広範なAPIスコープではなく、特定のタスクに限定された、使い捨ての「狭い能力（Narrow Capabilities）」を付与します。
4. **正常な停止と回復**: 信頼度が低い場合の人間へのエスカレーションや、冪等性キーを用いた状態保存により、エラー時でも途中から安全に再開できる仕組みを構築します。
5. **可観測性の確保**: 会話ログだけでなく、コンテキスト・グラフを用いて「なぜその決定が下されたか」という根拠を追跡可能にします。

最後に、MCP（Model Context Protocol）のようなオープンな仕様を活用し、モデルやランタイムが変わっても制御のポータビリティを維持することを推奨しています。

ベンチマークの結果、HomaはTCPと比較して、短いメッセージのテールレイテンシを10倍以上削減しつつ、大きなメッセージの転送効率も維持または向上させることが実証されました。これにより、AIクラスターにおける通信のボトルネックを解消し、計算リソースの利用効率を劇的に改善できる可能性があります。

## 価格逆転現象：安価な推論モデルが最終的により高コストになる理由

https://arxiv.org/pdf/2603.23971

**Original Title**: The Price Reversal Phenomenon: When Cheaper Reasoning Models End Up Costing More

AIモデルの公表されているAPI価格は実際の利用コストを正確に反映しておらず、安価なモデルの方が過剰な推論トークン消費や対話回数の増加により、結果的に高価になる「価格逆転現象」が32%のケースで確認された。

スタンフォード大学やカリフォルニア大学バークレー校の研究チームは、最新の推論モデル（RM）8種を12の多様なタスクで調査し、APIのカタログ価格と実際の推論コストの乖離を分析した。その結果、低価格なモデルがより高価なモデルよりも高い総コストを招く「価格逆転現象」を発見。例えば、Gemini 3 FlashはGPT-5.4よりカタログ価格が80%安いにもかかわらず、実際のコストは38%高かった。この要因を分析するためのシャプレイ値を用いたコスト寄与フレームワークを構築したところ、単一ターンタスクでは「思考トークン（Thinking tokens）」の過剰消費、複数ターンのエージェントタスクでは「対話ターン数」の増加が主因であることが判明した。また、同一クエリでも実行ごとにコストが最大9.7倍変動する「確率的性質」も指摘しており、カタログ価格に頼らないコスト予測と監視の重要性を提唱している。

## git worktree大増殖で困っていた - エムスリーテックブログ

https://www.m3tech.blog/entry/git-worktree-gc

AIエージェント開発などで乱立するgit worktreeを、マージ状況や作業状態を判定して自動で整理・削除する自作ツールとその活用法を紹介しています。

Gitのworktree機能は並列作業に非常に強力ですが、複数のAIエージェント（Claude Code等）を併用するとディレクトリが急増し、管理が煩雑になる課題があります。本記事では、この「worktree大増殖問題」を解決するために作成されたBashスクリプト『git-worktree-gc』を公開しています。このスクリプトは、単にディレクトリを消すのではなく、対象がmainブランチにマージ済みか、未コミットの変更がないか、detached HEADでないか、さらにClaudeのセッションが走っていないかといった安全性を機械的に判定して整理を行います。また、新規worktreeの作成・ブランチ切り・ディレクトリ移動を一挙に行う『kickoff』コマンドも紹介されており、開発効率を落とさずに環境を清潔に保つための具体的なTipsが凝縮されています。

## macOSにおけるフルディスクアクセスの更新

https://developer.apple.com/news/?id=p6zjojqw

**Original Title**: Updates to Full Disk Access in macOS

macOSの「フルディスクアクセス」権限に対し、AIエージェントの台頭によるプライバシーリスク増大を背景として、より明示的なユーザー同意を求める新たなセキュリティ制御が導入されます。

Appleは、macOSにおける「フルディスクアクセス（FDA）」の権限管理を強化することを発表しました。FDAは従来、バックアップアプリなどがシステムの制約を回避して動作するために提供されてきましたが、一部の開発者がユーザーの意図しない形で広範なデータ（メール、メッセージ、ブラウザ履歴など）にアクセスするリスクが懸念されています。特に、AIエージェントが自律的に動作する環境下では、この権限がもたらすプライバシーへの影響はより深刻なものとなります。これに対処するため、Appleはユーザーがリスクを十分に理解し、極めて明示的な操作を行った場合のみFDAを許可できるような新たな仕組みを導入します。開発者は、ユーザーが自身のデータとプライバシーについて情報に基づいた意思決定を行えるよう、より厳格なプロセスに対応する必要があります。
